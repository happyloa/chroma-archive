# 專案憲章（Constitution）

這份文件定下整個專案不隨功能變動的原則。`specs/` 底下每一份規格、計畫、任務都要符合這裡的條文；有衝突時以本文件為準，要改原則就先改這份文件並在 PR 說明理由。

## 1. 顏色是主角

介面本身只用兩個中性色（近黑 `#0E0E0E`、紙白 `#F4F2EE`）和一套灰階，畫面上的彩度留給年度色。任何新元件都不得自帶品牌色。每個頁面在 `<html>` 上設定 `--coty` 與 `--coty-ink`（年度色和它上面可讀的文字色），元件只能引用這兩個變數。

## 2. 內容先存在 DOM，WebGL 只負責加分

所有文字、色號、色值、設計發想都要以 HTML 輸出，關掉 JavaScript 也讀得到。WebGL 場景負責氛圍、轉場和產品 3D 預覽，不能是唯一的資訊來源。瀏覽器不支援 WebGL 或使用者開啟「減少動態效果」時，網站要退回靜態版面，功能不缺。

## 3. 效能有預算，超過就不合併

| 指標                                         | 上限        |
| -------------------------------------------- | ----------- |
| LCP（行動版、模擬 4G）                       | 2.5 秒      |
| CLS                                          | 0.05        |
| 首頁初始 JS（gzip，不含延遲載入的 three.js） | 120 KB      |
| three.js 與場景程式（gzip，延遲載入）        | 250 KB      |
| 單一 3D 模型（含貼圖）                       | 1.5 MB      |
| 桌機動畫幀率                                 | 60 fps      |
| 中階手機動畫幀率                             | 30 fps 以上 |

CI 跑 Lighthouse 與 bundle 大小檢查，超標的 PR 不合併。

## 4. 動態要有理由

每個動畫都要能回答「它幫使用者理解了什麼」：方向、層級、因果或狀態變化。純裝飾的動態只放在首頁 Hero 與頁面轉場。所有動畫都要有 `prefers-reduced-motion` 的替代行為。

## 5. 色彩資料誠實標示

Pantone 色票的官方數值屬於 Pantone LLC。網站上的 HEX、RGB、OKLCH 都是螢幕近似值，頁面要標註「螢幕近似色，非官方色彩標準」。不使用 Pantone 商標圖形、官方宣傳照或官方文案原文；年度色介紹一律自行撰寫。頁尾放非官方聲明。

## 6. 資料驅動，一年一筆

新增一個年度色只需要兩個動作：在 `data/colors.json` 加一筆，在 `src/content/years/` 加一篇 Markdown。不准為了某一年寫特例程式碼；有特殊需求（例如淺色、雙色年份）就把它做成資料欄位或通用規則。

## 7. 可及性是驗收條件

符合 WCAG 2.2 AA。鍵盤能操作全部功能，焦點樣式清楚可見。年度色上的文字依對比度自動選黑或白，對比不足時改用描邊或底板。

## 8. 規格先行

新功能先寫 `specs/NNN-name/spec.md`，再寫 `plan.md` 與 `tasks.md`，最後才寫程式。實作時發現規格錯了，先改規格再改程式。
